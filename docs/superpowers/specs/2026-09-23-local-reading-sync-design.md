# 本机阅读同步：设计

第一版是给一个人在本机用的网页。贴上微信读书 API Key 之后，同步书架上的书、划线和阅读进度，在书架和书页里回看。数据和 Key 都留在这台电脑上。

这一版不做：有声书、文章收藏、想法、书评、热门划线、阅读统计、「今天」页、Cookie 登录、多用户。

## 架构

本机只跑一个进程。浏览器只访问 localhost。API Key 存在本机 SQLite，由服务端带 `Authorization: Bearer` 调用 `POST https://i.weread.qq.com/api/agent/gateway`。

四个单元：

| 单元 | 职责 | 依赖 |
| --- | --- | --- |
| 网页 | 粘贴 Key、触发同步、展示书架和书页 | 只调用本机 HTTP |
| 本机 HTTP | 保存 Key、启动同步、读取本地书 | 同步、数据库 |
| 同步 | 按 `bookId` 写入；单本失败继续 | 微信读书客户端、数据库 |
| 微信读书客户端 | 把 gateway 请求发到微信读书 | 无本地状态 |
| 数据库 | 书、章节、划线、同步记录、Key | 无 |

技术选择：TypeScript、Node、Hono、better-sqlite3、Vite、React。开发时一个命令同时提供 API 和页面，页面请求发到同一来源。数据库文件是 `data/read-life.sqlite`，不进版本库。

## 远端接口

只用这四个 `api_name`：

| 接口 | 用途 |
| --- | --- |
| `/shelf/sync` | 取 `books`。不用 `albums`、`mp`、`archive` |
| `/user/notebooks` | 分页读取。`noteCount` 是划线数。`hasMore=1` 时，用本页最后一条的 `sort` 作为下次的 `lastSort` |
| `/book/bookmarklist` | 一本书的划线。以本次响应的 `updated` 作为该书全部划线，并用其中的 `chapters` 作为这些划线的章节 |
| `/book/getprogress` | 进度百分比（0–100）和 `readingTime`（秒） |

不调用章节目录、想法、热门划线和阅读统计接口。

## 同步

`POST /api/sync` 启动一次同步。已有同步在跑时，再次请求直接返回当前状态，不重入。`POST /api/sync?force=1` 是强制同步。

### 先取清单，再写库

1. 没有已保存的 Key：不写库，返回原因。
2. 请求 `/shelf/sync` 和全部分页的 `/user/notebooks`。其中任一失败（含 Key 被拒绝）：不修改书、划线、进度、在架状态，不写同步记录，把原因返回给页面。
3. 两份清单都成功之后，才进入写入。

笔记本里没有的书，划线数按 0。

### 每本书写什么

身份是 `bookId`。展示用的书名可以重复。

书架写入：更新书名、作者、封面、`readUpdateTime`、是否读完。本次 `books` 里没有、库里已有的书设为不在架。不删除它们的划线和进度。

进度：

- 本地还没有成功写入过 `/book/getprogress` 的结果，或者 `readUpdateTime` 与本地保存的值不同：请求 `/book/getprogress`，写入进度百分比和阅读秒数。
- 否则跳过。
- 强制同步不跳过。

划线：

- 本地还没有「划线已同步」标记，或者远端 `noteCount` 与本地保存的划线数不同：请求 `/book/bookmarklist`，在一个事务里用 `updated` 整本替换划线，并用响应里的 `chapters` 替换这些章节。
- `noteCount` 相同且已经同步过：跳过。划线数从 5 变成 0 时要拉一次，替换结果可以是空。
- 强制同步不跳过。
- 不因为 `reviewCount` 变化去重拉划线。想法不在这一版。

一次成功的划线替换会记下「划线已同步」，即使结果是 0 条。请求失败不清除旧划线，也不把标记改成已同步。

### 计数

每本书的进度和划线各自是跳过、写入或失败。

- 任一侧失败：这本书计入失败。另一侧如果已经成功，仍然保留那次写入。
- 两侧都没有失败，且至少一侧写入：计入更新。
- 两侧都跳过：计入跳过。

结束后写入一条同步记录：开始和结束时间、书架本数、更新本数、跳过本数、失败本数，以及失败书的 `bookId` 和原因。

## 网页怎么读

页面只读本地库。

`GET /api/key` 只返回是否已配置，不返回 Key。`PUT /api/key` 用一次 `/user/notebooks?count=1` 确认鉴权。失败则不替换已保存的 Key。成功才写入。

`GET /api/books` 只列出在架的书。按 `readUpdateTime` 倒序，用该时间的本地日历年份分段。没有 `readUpdateTime` 的书归入「未知」，排在有年份的组后面。同一年里仍按最近阅读时间倒序。每本书给出：`bookId`、书名、作者、封面、进度百分比、阅读秒数、划线数。进度还没有成功同步过时，百分比和阅读秒数为空，卡片上显示为未同步，不用笔记本列表里的 `readingProgress` 代替。

`GET /api/books/:bookId` 对已入库的书都可用，包括当前不在架的书。头部是封面、书名、作者、进度百分比、阅读时长、划线数。正文只含有划线的章节：章按 `chapterIdx` 升序，章内按 `range` 起点升序。`range` 缺失的划线排在该章最后。没有划线时头部仍在，正文为空状态。

返回给网页的任何 JSON 都不含 API Key。

## 失败

| 情况 | 库 | 页面 |
| --- | --- | --- |
| 没有 Key，或清单请求失败 | 书、划线、进度、在架状态不变 | 显示原因 |
| 某一本的进度或划线请求失败 | 该本保留上一次成功的内容；其他书照常写入 | 同步结果里有失败本数和原因 |
| 书不在本次成功返回的书架里 | 书架隐藏，划线保留 | 书架不列出；直接打开该书仍能看到留存内容 |
| 同步进行中又触发一次 | 不重入 | 看到当前这次的状态 |

## 测试

测试使用保存的接口响应，不访问微信读书。

必须覆盖：

- 划线数和 `readUpdateTime` 都没变，且两边都已经同步过：两个详情请求都不发。
- 划线数变化：整本替换划线；从有到 0 会清空划线。
- `readUpdateTime` 变化：更新进度；没变且已有进度：不更新。
- 强制同步：即使计数和时间都没变，也重拉划线和进度。
- 一本书的请求失败：其他书仍然写入；失败的那一本保留旧内容；同步记录计入失败。
- 书架或笔记本列表失败：书、划线、进度、在架状态都不变。
- 书架请求成功且某书缺席：该书不在架，划线还在，按 id 仍能读到。
- 书页排序：章节序号，然后是 `range` 起点。
- 书架分组：最近阅读时间的本地年份；缺失的归入「未知」。
- 网页接口的响应里没有 API Key。保存 Key 的鉴权失败时，旧 Key 还在。
